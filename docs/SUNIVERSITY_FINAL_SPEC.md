# SUNIVERSITY 최종 기능 명세서

- 문서 버전: 1.0
- 기준일: 2026-07-30
- 상태: 개발 기준선(Baseline)
- 저장 방식: MVP에서는 JSON 파일, 운영 전 데이터베이스로 교체

## 1. 제품 목표

SUNIVERSITY는 대학생과 연구팀이 앱 안에서 설문을 만들고, 다른 개인 또는
팀과 설문 응답을 교환해 연구에 필요한 응답을 확보하는 서비스다.

핵심 원칙은 다음과 같다.

1. 설문은 앱 안에서 작성하고 응답한다.
2. 설문 교환 기능은 설문별로 켜거나 끌 수 있다.
3. 교환 응답은 상호 의무가 모두 완료될 때까지 결과에서 제외한다.
4. 앱 사용자는 대학 인증이 필수다.
5. 외부 공유 링크 응답자는 가입과 대학 인증 없이 참여할 수 있다.
6. 포인트, 밸런스게임, 랭킹, 광고 보상 등 재미·보상 중심 기능은 제품 범위에서 제외한다.

## 2. 용어

| 용어 | 의미 |
|---|---|
| 일반 응답 | 앱 내부의 비교환 참여 또는 외부 링크를 통해 제출된 응답 |
| 교환 응답 | 직접 또는 자동 교환에 연결되어 제출된 응답 |
| 대기 응답 | 저장됐지만 교환이 완료되지 않아 통계에 반영되지 않는 응답 |
| 공개 응답 | 설문 결과, 응답 수, 통계, 그래프, CSV에 반영되는 응답 |
| 희망 교환 응답 수 | 팀이 한 번의 교환에서 상대 팀으로부터 받고 싶은 응답 수 |
| 필수 응답자 조건 | 학교, 학년, 전공, 대상 카테고리 등 매칭에 반드시 적용하는 조건 |
| 유효 문항 수 | 교환 구간을 계산하기 위한 응답 부담 기준 문항 수 |
| 교환 기준 시각 | 교환하는 두 설문의 마감 중 더 빠른 시각 |
| 교환 완료 시각 | 교환 기준 시각의 24시간 전 |

## 3. 사용자와 인증

### 3.1 앱 사용자

- 전화번호 로그인 후 대학 이메일 인증을 완료해야 앱 기능을 사용할 수 있다.
- 프로필은 학교, 학년, 전공, 응답자 조건 카테고리를 포함할 수 있다.
- 개인 교환에는 개인 신뢰도, 팀 교환에는 팀 신뢰도를 사용한다.

### 3.2 외부 링크 응답자

- 회원가입과 대학 인증 없이 설문에 참여할 수 있다.
- 외부 링크 응답은 일반 응답으로 제출 즉시 결과에 반영한다.
- 교환 완료 수와 신뢰도에는 포함하지 않는다.
- 학교·학년 등 인증 프로필 기반 통계에는 포함하지 않는다.

## 4. 설문 생성

### 4.1 설문 기본 정보

설문 작성자는 다음 정보를 설정한다.

- 제목과 설명
- 대표 카테고리 1개
- 추가 카테고리 태그 최대 3개
- 설문 마감일과 시각
- 목표 전체 응답 수
- 목표 교환 응답 수
- 외부 링크 응답 허용 여부
- 응답자의 익명 통계 열람 허용 여부
- 교환 기능 사용 여부
- 교환 방식: 직접, 자동 또는 둘 다
- 교환 단위: 개인 또는 팀
- 팀 설문인 경우 희망 교환 응답 수
- 필수 응답자 조건

### 4.2 질문 유형

지원 질문 유형은 다음과 같다.

1. 단답형
2. 장문형
3. 객관식
4. 체크박스
5. 드롭다운
6. 선형 척도
7. 객관식 그리드
8. 체크박스 그리드
9. 날짜
10. 시간
11. 파일 업로드

각 질문은 다음을 설정할 수 있다.

- 질문 내용
- 질문 설명
- 필수 응답 여부
- 선택지
- 최소·최대 선택 수
- 글자 수 또는 숫자 범위 등 유효성 검사
- 그리드 행·열
- 척도 범위와 양 끝 라벨
- 파일 형식, 크기, 개수 제한

MVP의 파일 업로드는 실제 바이너리 저장 대신 파일명, 크기, 형식과 가상 URL
메타데이터만 저장한다.

### 4.3 초안과 게시

- 질문이 0개인 설문은 초안으로 저장할 수 있다.
- 질문이 0개인 설문은 게시하거나 교환에 사용할 수 없다.
- 교환 기능을 켠 설문은 마감 시각이 필수다.
- 교환 가능한 설문은 게시 시점에 교환 완료 시각까지 시간이 남아 있어야 한다.

### 4.4 유효 문항 수와 구간

- 일반 질문은 1문항으로 계산한다.
- 객관식·체크박스 그리드는 행마다 1문항으로 계산한다.
- 설명과 섹션 제목은 계산에서 제외한다.

문항 구간은 다음과 같이 5개 단위로 구분한다.

- 1~5
- 6~10
- 11~15
- 16~20
- 이후 같은 규칙 반복

### 4.5 수정 제한

- 초안은 자유롭게 수정한다.
- 교환 신청이나 자동 매칭 대기가 생기면 질문, 선택지, 문항 수, 카테고리,
  교환 단위, 필수 응답자 조건을 잠근다.
- 구조를 변경하려면 기존 신청을 정리하고 새 버전으로 게시한다.
- 첫 응답 이후 질문 구조를 수정할 수 없다.
- 진행 중인 교환보다 이른 시각으로 마감을 단축할 수 없다.
- 마감 연장은 허용한다.

## 5. AI 질문 다듬기

1. 작성자가 질문을 직접 입력한다.
2. AI 다듬기 버튼을 누른다.
3. AI는 의미를 바꾸지 않고 이해하기 쉬운 수정안을 제시한다.
4. 화면은 원본, 수정본, 수정 이유를 함께 보여준다.
5. 작성자가 원본 또는 수정본을 선택한다.
6. 선택 후에도 직접 다시 편집할 수 있다.

AI가 설문을 임의로 게시하거나 원본을 자동 덮어쓰면 안 된다.

## 6. 교환 공통 규칙

- 개인 설문은 개인 설문하고만 교환한다.
- 팀 설문은 팀 설문하고만 교환한다.
- 본인 또는 같은 팀의 설문과 교환할 수 없다.
- 같은 사용자는 같은 설문에 한 번만 응답할 수 있다.
- 교환 응답은 `대기` 상태로 즉시 저장한다.
- 대기 응답의 내용과 진행 인원은 상대에게 공개하지 않는다.
- 화면에는 `교환 결과 대기 중`만 표시한다.
- 교환이 완료되면 양쪽 대기 응답을 하나의 처리로 공개한다.
- 교환이 취소되거나 만료되면 모든 대기 응답을 결과에서 제외한다.
- 필수 응답자 조건은 직접·자동 매칭의 선행 조건으로 사용한다.

## 7. 직접(선택) 교환

### 7.1 추천

신청 가능한 후보는 내 설문과 같거나 높은 문항 구간의 설문이다.

추천 순서는 다음과 같다.

1. 대표·추가 카테고리 유사도
2. 실제 유효 문항 수 차이
3. 신뢰도
4. 대기시간

신청할 수 없는 설문에는 교환 신청 버튼을 제공하지 않는다.

### 7.2 개인 직접 교환 흐름

1. 신청자가 상대 설문을 선택한다.
2. 신청자가 상대 설문에 응답한다.
3. 제출과 동시에 응답은 대기로 저장되고 상대에게 신청이 전달된다.
4. 상대가 신청을 확인하고 수락한다.
5. 상대가 신청자의 설문에 응답한다.
6. 상대의 최종 제출과 동시에 교환이 완료된다.
7. 두 대기 응답을 공개하고 양쪽 결과에 반영한다.

신청자가 응답을 최종 제출하지 않으면 신청을 생성하지 않는다.

### 7.3 직접 신청 한도

설문 하나를 기준으로 다음 한도를 각각 적용한다.

- 받은 직접 신청 중 수락 대기: 최대 10건
- 보낸 직접 신청 중 수락 대기: 최대 10건

한도를 초과할 신청은 사용자가 응답을 작성하기 전에 차단한다.

## 8. 자동 교환

### 8.1 후보 필터

자동 교환은 다음 조건을 모두 만족해야 한다.

- 동일한 개인·팀 교환 단위
- 동일한 문항 수 구간
- 필수 응답자 조건 충족
- 서로 교환에 필요한 적격 사용자 수 충족
- 교환 완료 시각 이전
- 자기 자신, 같은 팀, 중복 교환이 아님

### 8.2 우선순위

동일 구간 후보 중 다음 순서를 적용한다.

1. 실제 유효 문항 수 차이가 작은 순
2. 신뢰도 점수 80%
3. 대기시간 보정 20%

신규·저신뢰 사용자가 영구적으로 제외되지 않도록 대기시간을 반영한다.

### 8.3 자동 반복과 한도

- 설문별 목표 교환 응답 수에 도달할 때까지 자동 매칭을 반복한다.
- 완료 응답 수와 대기 중 예약 응답 수를 함께 확인해 목표를 초과하지 않는다.
- 자동 매칭으로 생성된 미완료 교환은 설문당 최대 10건이다.
- 목표 또는 한도에 도달하면 자동 대기를 일시정지한다.
- 교환이 취소되어 예약 수가 줄면 자동 대기를 재개한다.

## 9. 팀 교환

### 9.1 비대칭 응답 수

각 팀은 자신이 받고 싶은 희망 교환 응답 수를 독립적으로 정한다.
양 팀의 수가 같을 필요는 없다.

예시:

- A팀 희망 수: 3
- B팀 희망 수: 2
- B팀은 A 설문에 3개의 응답을 제공한다.
- A팀은 B 설문에 2개의 응답을 제공한다.

따라서 호환 조건은 다음과 같다.

- A팀의 적격 팀원 수 ≥ B팀 희망 수
- B팀의 적격 팀원 수 ≥ A팀 희망 수

적격 팀원은 활동 중이며 대학 인증과 상대 설문의 필수 응답자 조건을
충족하고, 상대 설문에 아직 응답하지 않은 서로 다른 사용자다.

### 9.2 참여 방식

- 교환 전 특정 팀원을 고정하지 않는다.
- 적격 팀원 중 먼저 최종 제출한 사용자가 응답 슬롯을 채운다.
- 한 사용자는 같은 설문의 슬롯을 하나만 채울 수 있다.
- 제출 당시 적격했던 사용자의 응답은 이후 팀을 탈퇴해도 유지한다.

### 9.3 전체 완료와 취소

- 양 팀이 약속한 모든 슬롯을 채워야 교환이 완료된다.
- 한 슬롯이라도 교환 완료 시각까지 비면 전체 교환을 만료 처리한다.
- 전체 완료 전에는 어느 응답도 결과에 반영하지 않는다.
- 매칭 후 적격 인원 부족이 확정되어 이행이 불가능하면 즉시 취소할 수 있다.
- 결과 공개는 전체 단위지만 신뢰도는 각 팀이 실제 이행한 슬롯 단위로 계산한다.

## 10. 마감과 취소

- 교환 기준 시각은 두 설문 마감 중 더 빠른 시각이다.
- 교환 완료 시각은 교환 기준 시각의 24시간 전이다.
- 교환 완료 시각이 지나면 신규 신청, 수락, 자동 매칭을 막는다.
- 그때까지 완료되지 않은 교환은 자동 취소한다.
- 취소된 대기 응답은 통계에 반영하지 않는다.

책임 규칙:

- 응답 제출 전 신청 철회: 무패널티
- 유효한 교환 신청을 받은 뒤 미응답·수동 취소: 책임 측 신뢰도 하락
- 자동 매칭 후 수동 취소·미응답: 책임 측 신뢰도 하락
- 이미 의무를 완료한 상대방: 신뢰도 불이익 없음
- 신고로 설문이 무효화되거나 시스템 오류로 취소: 양측 무패널티

## 11. 신뢰도

개인과 팀은 별도의 신뢰도를 가진다. 신규 점수는 30점이다.

초기 점수의 급격한 변동을 줄이기 위해 다음 보정 공식을 사용한다.

```text
신뢰도 = round(100 × (기한 내 완료 슬롯 + 1.5) / (확정 의무 슬롯 + 5))
```

- 점수 범위는 0~100이다.
- 가상 이력 5개와 완료율 30%를 초기값으로 사용한다.
- 실제 이력이 쌓일수록 실제 완료율에 가까워진다.
- 직접 교환은 유효한 선행 응답이 제출되어 상대에게 의무가 생긴 시점부터 계산한다.
- 자동 교환은 시스템이 매칭을 확정한 시점부터 계산한다.
- 팀은 완료한 슬롯과 약속한 슬롯을 기준으로 계산한다.
- 거절 전 철회, 시스템 취소, 신고로 인한 무효화는 분모에서 제외한다.

## 12. 응답과 결과

### 12.1 반영 시점

| 응답 종류 | 저장 시점 | 결과 반영 시점 |
|---|---|---|
| 앱 내부 일반 응답 | 제출 즉시 | 제출 즉시 |
| 외부 링크 일반 응답 | 제출 즉시 | 제출 즉시 |
| 직접 교환 응답 | 제출 즉시, 대기 상태 | 전체 교환 완료 시 |
| 자동 교환 응답 | 제출 즉시, 대기 상태 | 전체 교환 완료 시 |

### 12.2 작성자 결과

- 전체 응답 수와 완료·대기 응답 구분
- 개별 공개 응답
- 문항별 요약
- 질문 유형에 맞는 그래프와 통계
- 응답 데이터 표
- CSV 다운로드
- 학교, 학년, 응답자 조건 카테고리 필터

작성자는 동의받은 프로필 항목만 볼 수 있다. 이름, 전화번호, 이메일은
설문에서 별도로 수집하지 않는 한 결과에 제공하지 않는다.

### 12.3 응답자 결과

- 작성자가 결과 열람을 허용한 경우 익명 집계와 그래프를 볼 수 있다.
- 개인 응답, 학교, 학년, 조건 카테고리로 다른 응답자를 식별할 수 없다.
- 교환 응답자는 자신의 교환이 완료된 후 결과를 볼 수 있다.
- 외부 응답자는 제출 영수증 토큰으로 결과를 볼 수 있다.
- 소수 집단 재식별을 막기 위해 5명 미만인 세부 집단 통계는 응답자에게 숨긴다.

## 13. JSON MVP 상태

### 13.1 주요 컬렉션

- `users`
- `universities`
- `teams`
- `surveys`
- `responses`
- `exchanges`
- `auto_match_queue`
- `ai_usage`
- `notifications`

### 13.2 응답 공개 상태

- `published`: 결과에 반영
- `pending`: 교환 완료 대기, 결과에서 제외
- `discarded`: 취소·만료로 결과에서 제외

### 13.3 교환 상태

- `awaiting_acceptance`: 직접 교환 수락 대기
- `in_progress`: 수락 또는 자동 매칭 후 응답 진행
- `completed`: 모든 의무 완료 및 응답 공개
- `cancelled`: 사용자 취소
- `expired`: 교환 완료 시각 초과
- `invalidated`: 신고 또는 시스템 사유로 무효화
